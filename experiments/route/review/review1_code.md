## Findings

1. **should-fix before launch** — `pool.py:56-59` (STRATA) / `train_route.py:105-120`. P4 is stated at k = 3 ("≥ 0.9 on PP runs at k = 3", "all-H words at k = 3") and §5 promises every in-range table split by "words with a P". No pp3 / all-H stratum exists (`forced_word('none')` is implemented but unused) and `evaluate` records only stratum means, so neither P4 nor the promised split can be computed; in{k} mixes all-H words (100 % at k = 1, 13 % at k = 8) with P-words. S8 is the most expensive arm (≈ 2 T4-h), so this is not recoverable cheaply. Fix: add `("pp3", (3, "pp"))`, `("none3", (3, "none"))`, `("none4", (4, "none"))` to STRATA, and in `evaluate` record `acc_P` / `route_acc_P` / `acc_noP` per stratum using `hasP = (fb["q_word"][sl][sel] == 1).any(-1)` (same in `train_neural.evaluate`).

2. **should-fix before launch** — `train_route.py:121-132`, `analyze.py:165-170`. The probe R² is pooled over in8 + len16 + len32 + alt32 into one number, so P8's "≥ 0.8 in range and ≥ 0.5 at k = 16–32" cannot be read, and `residual()` prints the same pooled value on every stratum row. Also the labels: after an early halt the committed route's states repeat, so a mis-halting router duplicates (feature, label) pairs across the random half split. Fix: fit `ridge_r2` per stratum (`res[r][name]["probe_r2"]`) over states `≤ steps` only. Design-level caveat for the same prediction: the probed vector is a function of (symbol, context) through one cross-attention read of that symbol's pair, so remaining distance is not linearly available to any Markov router — the planted exact router gives R² = −0.2 / −0.5. P8's probe clause will fail by construction (expressivity, not a finding); say so in DESIGN.md or probe something the router can carry.

3. **should-fix before launch** — `train_route.py:186-197` vs `train_neural.py:125-130`. P4 asks for the pooling-for-selection contrast (accuracy on P-at-depth-d words) "for RM and LF/LR"; only the neural trainer records `acc_by_Pdepth`. Fix: copy the `hasP[..., d-1]` accumulation into the routed curve (route and answer accuracy). While there, record answer accuracy by k for routed arms too: `t95_of` uses route accuracy, which censors RM-λ0 (halts late by prediction P6) even when its answers are right.

4. **should-fix (labeling)** — `pool.py:58`, DESIGN §2/P3. alt4/alt6/alt8 (PHPH, PHPHPH, PHPHPHPH) are training-family words: measured training frequency 4.1e-3 / 4.7e-4 / 8.3e-5 per query, i.e. ≈ 9,500 / 1,100 / 190 occurrences over a 6k-step run. Tables must not file them under "new orders"; only pp* is unseen in order, alt16/32 in length. P3's headline should rest on pp4–pp8 (+ pp16/32).

5. **minor** — `data.py:113-121`. `forced_word('pp')` plants a run of 2–3 into a word sampled with `max_prun=3`, so runs merge into length 4–5 (e.g. PPPHP + start 3 → PPPPP…). Harmless for "unseen", but the stratum is not "PP/PPP" as documented; sample with `max_prun=1` before planting if the class matters.

6. **minor** — `run_route.py:72-77`. On a failed stack the retry of the first half runs inside the `except` block; if it raises, the second half is never attempted in that session (resumable later, but wastes the session). Wrap each half in its own try.

7. **minor** — `experiments/route/derive/wander.py`. With `readout(cfg, 0.0)` every readout row sums to 1, so `p_any = q.sum(-1)` is identically 1.000 ("mass halting on any answer" is meaningless). The oracle-share numbers in §5 are unaffected (they are defined with the 1/16 uniform mass in the denominator, as the text says). §5 also has two "wandering mass" bullets, the second describing a quantity the script does not compute.

8. **minor (doc/code mismatches)** — DESIGN §4 says pairs pass "through one learned pre-norm self-attention layer so that a pair can also see its neighbours"; `router.py:65-73` has a per-token MLP only (the prev slot makes it unnecessary; pick one). §2 says d = 328 for the baselines; `train_neural.py:32` uses 344 (328 would not hold five 66-dim slots: `FrozenSymbols.exact` false). §6/§4 say the plant is "within one unit of the init"; head columns have norm 3 and bias 4 (`router.py:113`, test allows 4.5). §9 says the probe reads "the router's MLP input"; code probes the post-MLP head input (`features`, after `head_norm`).

9. **minor** — `analyze.py:124-134`. `counts()` bins at 0.6/0.9; P1's thresholds are 0.95 (route) and 0.98 (answer), so the per-seed counts P1 needs are not printed. Add those bins (or per-prediction thresholds). `residual()` prints `nan` for the index arm's R² where other cells print "–".

10. **minor (design)** — P7's falsifier ("RM-idx above coverage: the strata leak the word") is unreachable: `kind="index"` is a table over t with no input (`router.py:49-50, 78-81`), so it cannot exceed coverage. It is a valid state-blind null; a leak test would need a context-reading, state-blind router (constant state token).

11. **note** — reproducibility: the init seed is `1000003·seeds[0] + sum(seeds)` (`train_route.py:154`, `train_neural.py:80`), so a resumed grid with a different stack composition re-initializes the remaining runs differently; pools and strata are per-seed and paired across arms as the design requires (`s·7919+11`, `s·7919+12345`). `run_stack` lacks rung 0's `_group_ok` guard; grouping in `run_route.py` makes it safe, but a direct call with mixed configs would silently take `cfgs[0]`'s settings.

## Verdict

The numerical core — generator and its invariants, transition tables, the exact route marginal (state and step-indexed), committed routes, route-accuracy check, remaining distance, the stacked router's attention and its planted rule, teacher forcing, per-run slicing in `evaluate`, the 5-slot baselines and their LR/eval-at-T rows, grouping and the Kaggle job — is correct as far as independent brute force and hand references can establish, and the tests exercise the right things. Nothing here would silently corrupt a trained number. What is missing is bookkeeping that the preregistered predictions depend on: P4's k = 3 strata and the in-range P/no-P split (1), per-stratum probe R² (2), RM's by-depth curve (3), and the "new orders" label on alt ≤ 8 (4). Items 1–3 are small, change no training, and are unrecoverable from the stored means, so apply them before the main grid; the pilot can run on the current code. Reconsider P8's probe clause: it fails for any Markov router by construction.
